T3 Tutor Loop

One real task, every turn shown. The graph on the left follows the conversation on the right as you scroll. Between each learner message and the tutor's reply, the dashed backstage strip shows the silent part: the orchestrator decides what the tutor is allowed, and the engine builds the tutor's prompt and tools from that decision.

  1. Learner

    Works in the code. Talks only to the tutor.

  2. Orchestratorsilent

    Reads the graph, assesses each turn, updates the graph, and picks which templates, tools and state the tutor gets.

  3. Enginecode

    Turns that pick into the tutor's system prompt (templates filled with state) and its tool list.

  4. Tutorthe only voice

    Teaches with exactly the kit it was given, nothing more.

Graph updates come from the orchestrator here. They could also pass through the engine; nothing else in the scenario would change. Phase 1 runs no code on the server: lines marked “pasted” are what the learner pastes from VS Code.
